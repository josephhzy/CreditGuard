## Intended Use

### Primary

Estimate probability of default (PD) for new applications to an unsecured consumer credit product, to support — not replace — an underwriter's decision within a three-band decisioning layer (approve / review / decline).

### Secondary

1. Flag deteriorating existing accounts for early intervention via score drift.
2. Provide model-risk and compliance teams with explanations, threshold logic, and monitoring signals for SR 11-7 / Basel IRB-style governance reviews.
3. Act as a reference implementation of a credit-decisioning pipeline (data ingestion → features → model → calibration → thresholding → serving → monitoring).

### Users

- Credit risk analysts
- Underwriting teams (review-queue)
- Model risk management

### Deployment context

**Decision support**, not autonomous decision-maker. Adverse actions against individual applicants always require human review — see `governance/ADVERSE_ACTION.md`.

---

## Out-of-Use Policy

This model must **not** be used for:

- Autonomous credit decisions without a human in the loop for the decline band.
- Regulatory compliance certification — the fairness analysis here is *illustrative*, not an audit.
- Populations outside the training distribution (different geographies, product types, economic regimes) without revalidation.
- Pricing, collections, or recovery workflows — this is a PD model, not a full EL = PD × LGD × EAD system.
- Any context where a SHAP-derived reason code is treated as *causal* rather than *correlational*.

### Preprocessing lineage

1. Schema validation via `data/schema_validator.py`.
2. Leakage scan via `data/leakage_scanner.py` (blacklist of post-outcome columns, temporal-ordering checks, correlation > 0.95 flags, future-record aggregation checks).
3. Star-schema join with one-to-many aggregation (mean/max/min/sum/count for numerics, mode/nunique for categoricals). Grandchild tables (e.g. `bureau_balance`) go through two-level aggregation.
4. ~80 engineered features across 7 families (count varies with dataset column availability), reduced to **15 selected** via Boruta (200 iters, alpha 0.05) + VIF threshold 10.0.

## Ethical Considerations

- **Material impact on individuals.** Credit scoring determines access to financial services; errors affect individuals' ability to obtain loans.
- **Disparate impact risk.** Even features not explicitly encoding protected attributes can correlate with them. The Home Credit dataset has no race/ethnicity columns and only weak proxies for protected classes; a production deployment requires access to actual protected-class data and a fair-lending review by qualified compliance staff.
- **Explanation fidelity.** SHAP values are *correlational attributions* of the model's score, not causal explanations of default. Adverse-action notices generated from SHAP are consistent with ECOA-style explanations ("what the model weighed most") but do not meet a causal standard. See `governance/ADVERSE_ACTION.md`.
- **Population drift.** Economic regime shifts move the PD → default relationship (concept drift) as well as the input distributions (covariate shift). A stale model makes worse decisions silently. See `monitoring/RETRAIN_POLICY.md`.
- **Monoculture risk.** If many lenders run similar models, applicants rejected by one are likely rejected by many, amplifying the welfare cost of systematic errors.

---

## Caveats and Recommendations

1. **Public dataset.** Distributions, default definitions, and feature availability may not match any specific institution's book.
2. **No LGD / EAD / recoveries.** This model predicts PD only. Expected Loss requires `PD × LGD × EAD`, and a full book-level risk picture requires capital and reserve modelling beyond the model card.
3. **No live feedback loop.** Model decay is inferred from distributional statistics (PSI / KS / JSD) and calibration drift, not from observed default outcomes on scored applicants.
4. **Fairness results warrant review, not certification.** AIR is 0.81 on gender at the decline gate (a narrow pass of the EEOC four-fifths rule, which sets the bright line at AIR ≥ 0.80) and 0.61 across education levels (a clear fail). At tighter slicings — gender at the 0.15 approve gate, AIR 0.71 — even the gender slice fails. Proxy encoding (via employment, education, document features) is non-trivial. See `governance/FAIRNESS_REPORT.md` for the four-stage mitigation pipeline.
5. Both LightGBM and XGBoost have near-identical discrimination (ROC-AUC 0.762 vs 0.761), but LightGBM has materially better raw calibration (Brier 0.177 vs 0.210). For threshold-based decisioning this calibration gap was the binding governance constraint — see `evaluation/CALIBRATION.md`.
6. **Do not treat SHAP as causal.** The adverse-action output surfaces the features the model used, not the reasons for the outcome in the real world.

## Deployment Requirements

For production deployment, the following would be required before this model touches any credit decision:

1. Lender-specific re-training and re-calibration on in-book data.
2. LGD and EAD models, with integration into an Expected Loss pipeline.
3. Fair-lending review by qualified compliance staff on real protected-class data.
4. Model validation dossier aligned with SR 11-7 (US) / PRA SS1/23 (UK) / MAS FEAT (SG).
5. Challenger model(s) from a different family (e.g. monotonic GBM, neural additive model) to stress-test the LightGBM championship.
